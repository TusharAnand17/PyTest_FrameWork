User Story
As a user,
I want to search and view books from the web table,
So that I can find books based on subject, author, and price.

Acceptance Criteria
- User should be able to view all books in the table.
- User should be able to identify books based on subject.
- User should be able to verify books written by a specific author.
- User should be able to identify books whose price is greater than 1000.
- User should be able to verify total number of books available in the table.
- Subject comparison should be case-insensitive.
- System should handle situations where no matching records are found.
- User should be able to verify that every book has: Book Name, Author, Subject, Price.

Positive Scenarios
PS-01: User views all available books and sees required book details.
PS-02: User searches by subject and gets subject-matching books using case-insensitive comparison.
PS-03: User filters or verifies books by a specific author.
PS-04: User identifies books with price greater than 1000.
PS-05: User verifies displayed total count matches listed books.

Negative Scenarios
NS-01: No books match the entered subject and system shows no-match result.
NS-02: No books match the entered author and system shows no-match result.
NS-03: No books are above a very high price threshold and system shows no-match result.

Edge Cases
EC-01: Subject search term uses mixed letter case and still returns expected records.
EC-02: Subject search term includes leading/trailing spaces and still matches correctly.
EC-03: Books priced exactly 1000 are excluded from results for greater-than-1000 filter.
EC-04: Empty search term returns all books or a clear validation message without failure.

Validations
VAL-01: Every visible book row has Book Name, Author, Subject, and Price values.
VAL-02: Subject matching is case-insensitive.
VAL-03: Price comparison uses strict greater-than for threshold 1000.
VAL-04: No-match scenarios display a clear business message and empty result list.
VAL-05: Displayed total count equals number of visible rows.

Boundary Conditions
BC-01: Price equals 1000 should not appear in greater-than-1000 results.
BC-02: Very large threshold produces no records with expected no-match behavior.
BC-03: Empty subject input is handled gracefully.
